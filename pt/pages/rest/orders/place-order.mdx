Submeta uma ou mais ordens. O endpoint aceita um lote — os resultados por ordem regressam em `data.createdSessions`, **posicionalmente** em relação ao seu array `orders` de entrada. Cada entrada é ou um resultado bem-sucedido `{ matched, unmatched }` ou uma falha `{ error, errorType }`.

## Pedido {#request}

`POST /session/v3/place`

<CodeGroup>
```bash curl
curl -X POST https://api.4casters.io/session/v3/place \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "orders": [
      {
        "gameID": "688c0516fbc14da0c202d426",
        "type": "moneyline",
        "side": "5c12bc1ce0daba000f47ba8b",
        "odds": -175,
        "bet": 100,
        "orderType": "post",
        "userReference": "docs-example"
      }
    ]
  }'
```

```json Corpo JSON
{
  "orders": [
    {
      "gameID": "4CASTER_GAME_ID",
      "type": "moneyline | spread | total | moneyline1x2",
      "side": "PARTICIPANT_ID | over | under | yes | no",
      "market": "PARTICIPANT_ID | draw",
      "odds": -110,
      "bet": 100,
      "number": 3.5,
      "orderType": "limit | post | postArb | fillAndKill | fillOrKill",
      "expirationMinutes": 10,
      "userReference": "OPTIONAL_CLIENT_SIDE_IDENTIFIER"
    }
  ]
}
```
</CodeGroup>

## Tipos de ordem {#order-types}

### `limit` {#limit}

O tipo de ordem predefinido. Executa contra qualquer liquidez correspondente ao seu preço ou melhor como taker (com comissão de taker), e deixa o restante em espera no livro como maker. Uma ordem `limit` pode terminar totalmente correspondida, totalmente em espera, ou parcialmente correspondida com o restante em espera.

### `post` {#post}

Cria uma oferta em espera. Se a ordem **fosse corresponder** a liquidez existente no momento da colocação, o servidor rejeita-a (`rejected_order_type_rules`, p. ex. `"post order cannot have matches"`).

### `postArb` {#postarb}

Comporta-se como `post`, mas pode publicar **mesmo quando a ordem corresponderia**, **apenas se** as suas odds americanas estiverem a menos de **1%** das odds da ordem em espera à qual corresponderia. Se a diferença de preço for superior a 1%, a colocação é rejeitada.

Exemplos:

- Melhor oferta a **+100** e você publica **+100** — `post` é rejeitada (iria corresponder); `postArb` é permitida.
- Melhor oferta a **+200** — `postArb` a **+190** é rejeitada (demasiado longe de **+200**). Cerca de **+198** está no limite da banda de 1% face a **+200**.
- Melhor ordem a **−200** — a banda estende-se até cerca de **−202** no lado negativo (mesma regra de 1%).
- Com **+100** no livro, **−101** é o limite de referência do outro lado para a tolerância de 1%.

`postArb` evita as **comissões de taker** de uma transação normal — não lhe são cobradas comissões de taker neste fluxo, como seriam se tomasse a liquidez em espera como taker.

As ordens colocadas como `postArb` são sinalizadas com `isPostArb: true` nas atualizações do respetivo [feed de utilizador](/pt/pages/streaming/user-feed) e [feed de preços](/pt/pages/streaming/price-feed); o campo é omitido para os outros tipos de ordem. A própria resposta de colocação não inclui a flag.

### `fillAndKill` {#fillandkill}

Executa imediatamente como taker contra o volume que estiver disponível ao seu preço ou melhor, e cancela o restante. Uma `fillAndKill` nunca fica em espera no livro.

Uma execução **parcial** é um resultado bem-sucedido: se enviar `bet: 1000` e só existirem $400 de liquidez correspondível, é executado por $400 e os restantes $600 são cancelados — a resposta é um sucesso, não um erro. A ordem é rejeitada (`rejected_order_type_rules`, `"fill and kill has no matches"`) apenas quando não existe liquidez correspondível de todo. Consulte os cenários Fill And Kill nos [exemplos](#examples) abaixo.

### `fillOrKill` {#fillorkill}

Tudo-ou-nada. A **totalidade** do seu `bet` tem de corresponder imediatamente ao seu preço ou melhor, caso contrário a ordem inteira é rejeitada — incluindo quaisquer execuções que tenha feito pelo caminho, que são revertidas. Uma `fillOrKill` nunca fica em espera no livro, e nunca fica parcialmente executado.

Use-a quando uma posição parcial for pior do que nenhuma posição, por exemplo quando a ordem é uma perna de uma cobertura que só pode executar na totalidade.

As rejeições trazem `errorType: rejected_order_type_rules` com uma de duas mensagens, que distinguem «não havia nada» de «não havia o suficiente»:

- `"fill or kill has no matches"` — sem liquidez correspondível ao seu preço.
- `"fill or kill matched but not fully"` — alguma liquidez correspondeu, mas não o seu volume total. Essas execuções foram revertidas.

<Note>
  Um resíduo de **$10 ou menos** conta como completo: uma `fillOrKill` de $1,000 que corresponde $992 tem sucesso, porque os $8 que não puderam ser executados estão abaixo do tamanho mínimo que alguma vez poderia ficar em espera no livro. Um resíduo superior a $10 rejeita a ordem.
</Note>

### Cenário 5 — Fill or Kill, liquidez insuficiente {#scenario-5-fill-or-kill-not-enough-liquidity}

`fillOrKill` é a contraparte tudo-ou-nada de `fillAndKill`. Onde uma `fillAndKill` de $1,000 contra $400 de liquidez executa $400 e cancela o resto, uma `fillOrKill` rejeita a ordem inteira e reverte esses $400 — nunca fica parcialmente executado.

<CodeGroup>
```json Pedido
{
  "orders": [
    {
      "gameID": "688c0516fbc14da0c202d426",
      "type": "moneyline",
      "side": "5c12bc1ce0daba000f47ba8b",
      "odds": -110,
      "bet": 1000,
      "orderType": "fillOrKill",
      "userReference": "docs-fillorkill-partial"
    }
  ]
}
```

```json Resposta
{
  "data": {
    "createdSessions": [
      {
        "error": "fill or kill matched but not fully",
        "errorType": "rejected_order_type_rules"
      }
    ]
  }
}
```
</CodeGroup>

Sem qualquer liquidez correspondível, a mesma ordem é rejeitada com `"fill or kill has no matches"`.

### Cenário 6 — `postArb` vs `post` quando o livro corresponderia {#scenario-6-postarb-vs-post-when-the-book-would-match}

`post` rejeita uma ordem que fosse corresponder a liquidez em espera (por exemplo, melhor oferta a **+100** e você tenta publicar **+100**). `postArb` permite essa situação quando as suas odds estão a menos de **1%** da ordem à qual corresponderia — pelo que a mesma publicação a **+100** pode ter sucesso como `postArb`, e você evita as comissões de taker que pagaria numa transação normal. Se o seu preço estiver demasiado longe da cotação em espera (p. ex. melhor oferta a **+200** mas envia **+190**), `postArb` é rejeitada.

<CodeGroup>
```json Pedido
{
  "orders": [
    {
      "gameID": "688c0516fbc14da0c202d426",
      "type": "moneyline",
      "side": "5c12bc1ce0daba000f47ba8b",
      "odds": 100,
      "bet": 50,
      "orderType": "postArb",
      "userReference": "docs-postarb-same-line-as-offer"
    }
  ]
}
```
</CodeGroup>

### Cenário 7 — `moneyline1x2` (três vias no futebol) {#scenario-7-moneyline1x2-soccer-three-way}

`moneyline1x2` é o mercado de três vias do futebol — casa / fora / empate — colocado como uma aposta yes/no sobre o resultado indicado por `market`. Abaixo, **yes no empate** a +250.

<CodeGroup>
```json Pedido
{
  "orders": [
    {
      "gameID": "65f0c3...",
      "type": "moneyline1x2",
      "side": "yes",
      "market": "draw",
      "odds": 250,
      "bet": 50,
      "orderType": "post",
      "userReference": "docs-ml1x2-yes-draw"
    }
  ]
}
```
</CodeGroup>

Para apostar que a **equipa da casa não ganha**, envie `side: "no"` e defina `market` para o id do participante da casa.

## Atraso ao vivo {#live-delay}

As ordens colocadas num jogo marcado como ao vivo seguem estas regras:

1. Se a ordem não corresponder a nenhuma liquidez existente, é colocada imediatamente.
2. Se a ordem corresponder a liquidez existente, incorre num atraso antes da execução.
3. Ligas diferentes têm períodos de atraso ao vivo diferentes:
    - **NFL, UFCMMA, NCAAF** — 3 segundos.
    - **NCAAB, NBA** — 5 segundos.
    - **ATP, WTA** — 8 segundos.
    - **Predefinição** — 10 segundos.
4. Após o atraso, a ordem tenta executar:
    - Se as odds melhorarem, corresponde instantaneamente.
    - Se as odds piorarem, não corresponde.
