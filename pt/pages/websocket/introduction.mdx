---
title: 'API de Ordens da 4casters'
---

A API de Ordens da 4casters suporta colocação de ordens em tempo real, cancelamento e gestão de sessão através de uma ligação WebSocket em bruto.

## Endpoints {#endpoints}
- **API de Ordens**: `wss://orders-api.4casters.io/orders/ws`

## Autenticação {#auth}

A ligação autentica-se com um token da 4Casters. Envie o token no cabeçalho
`Authorization` no handshake do WebSocket. O servidor deriva o utilizador
a partir do token — **sem nome de utilizador no URL**.

### Obter um token {#get-a-token}

Inicie sessão com o seu nome de utilizador e palavra-passe da 4Casters chamando o endpoint
`/user/login` da API REST da 4Casters. A resposta inclui um token que pode usar
aqui.

Consulte [`POST /user/login` na documentação da API REST da 4Casters](/pt/pages/rest/authentication).

### Ligar {#connect}

<CodeGroup>
```javascript JavaScript
const WebSocket = require('ws');
const token = process.env.FOURCASTERS_TOKEN;
const ws = new WebSocket('wss://orders-api.4casters.io/orders/ws', {
  headers: { Authorization: token },
});
```
</CodeGroup>

## Formato das mensagens {#message-format}

Cada pedido do cliente é um 2-tuplo `[messageType, payload]`. Cada payload deve incluir um `requestID` gerado por si; o servidor devolve-o de volta para que possa correlacionar as respostas.

<CodeGroup>
```json Pedido
[
  "messageType",
  {
    "requestID": "YOUR_REQUEST_ID",
    "...": "..."
  }
]
```
</CodeGroup>

As respostas do servidor são objetos JSON com `requestID` mais `data` (sucesso) ou `error` (falha):

<CodeGroup>
```json Sucesso
{
  "requestID": "YOUR_REQUEST_ID",
  "data": { "...": "..." }
}
```

```json Erro
{
  "requestID": "YOUR_REQUEST_ID",
  "error": "human-readable error"
}
```
</CodeGroup>
