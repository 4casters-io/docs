O feed de preços transmite atualizações de mercado/livro de ordens como mensagens JSON através de uma ligação WebSocket em bruto.

<CodeGroup>
```javascript JavaScript
// price_feed_quickstart.js 
const WebSocket = require('ws'); 
const token = process.env.FOURCASTERS_TOKEN; 
 
function connectPriceFeed() { 
  const ws = new 
  WebSocket('wss://streaming-api.4casters.io/price-stream', { 
    headers: { Authorization: token }, 
  }); 
 
  let pingTimer; let lastPong = Date.now(); 
 
  ws.on('open', () => { 
    console.log('price stream connected'); 

    // Optional: narrow the feed to specific games / leagues / sports.
    // Omit this block to receive all market updates (default). 
    ws.send(JSON.stringify({ 
      type: 'subscribe', 
      gameIDs: [], 
      leagueIDs: ['NBA'], 
      sportIDs: [], 
      replace: true, 
    })); 

    pingTimer = setInterval(() => { 
      if (ws.readyState === WebSocket.OPEN) ws.ping(); 
      if (Date.now() - lastPong > 30000) { 
        console.warn('price stream: missed pong >30s, closing'); 
        ws.terminate(); 
      } 
    }, 10000); 
  }); 
 
  ws.on('pong', () => { lastPong = Date.now(); }); 
 
  ws.on('message', (buf) => { 
    try { 
      const msg = JSON.parse(buf.toString()); 
      console.log('price update:', JSON.stringify(msg, null, 2)); 
    } catch { console.log('price update (raw):', buf.toString()); } 
  }); 
 
  ws.on('error', (e) => console.error('price stream error:', e.message)); 
 
  ws.on('close', (code, reason) => { 
    console.log(`price stream closed: ${code} ${reason}`); 
    clearInterval(pingTimer); 
    setTimeout(connectPriceFeed, 1000); 
  }); 
} 
connectPriceFeed();
```
</CodeGroup>

## Ping/Pong {#pingpong}
Ambos os feeds suportam o `ping/pong` padrão do WebSocket. Pode fazer `ping()` proativamente num intervalo e acompanhar o `pong` para verificar a vivacidade da ligação.

## Subscrições {#subscriptions}

Por predefinição, um cliente ligado recebe todas as atualizações de mercado de todos os desportos e ligas. Para restringir o fluxo, envie um dos seguintes comandos como frame de texto JSON depois de o socket estar `open`. Os comandos produzem efeito durante a vida da ligação.

Um cliente que nunca envia um comando de subscrição permanece em modo de difusão total, pelo que as integrações existentes continuam a funcionar sem alterações.

### Subscrever por gameID, liga ou desporto {#subscribe-by-gameid-league-or-sport}

Instala um filtro. Os `gameIDs` são cadeias hex de 24 caracteres de ObjectID do Mongo; os `leagueIDs` são códigos curtos como `NBA` / `MLB` / `EPL`; os `sportIDs` são tokens em minúsculas como `basketball` / `baseball` / `soccer`.

<CodeGroup>
```json Substituir (recomendado)
{
  "type": "subscribe",
  "gameIDs": ["62619dce25e2fb049a71cc2e"],
  "leagueIDs": ["NBA"],
  "sportIDs": [],
  "replace": true
}
```
```json Aditivo
{
  "type": "subscribe",
  "gameIDs": [],
  "leagueIDs": ["MLB"],
  "sportIDs": [],
  "replace": false
}
```
</CodeGroup>

- `replace: true` limpa quaisquer subscrições existentes nesta ligação e instala as novas listas. Muda a ligação para modo filtrado.
- `replace: false` acrescenta as novas chaves ao que a ligação já subscreve.

Receberá uma atualização se o respetivo `gameID`, `parentGameID`, `league` ou `sport` corresponder a alguma das suas subscrições.

### Anular a subscrição {#unsubscribe}

Remove chaves específicas. A ligação mantém-se no modo atual (filtrado ou subscrever-tudo).

<CodeGroup>
```json JSON
{
  "type": "unsubscribe",
  "gameIDs": [],
  "leagueIDs": ["MLB"],
  "sportIDs": []
}
```
</CodeGroup>

### Subscrever tudo {#subscribe-to-everything}

Apanha-tudo explícito. Útil se anteriormente restringiu via `subscribe` e quer voltar a alargar sem religar. Limpa quaisquer subscrições por chave na ligação.

<CodeGroup>
```json JSON
{ "type": "subscribeAll" }
```
</CodeGroup>

### Semântica de encaminhamento {#routing-semantics}

- Uma subscrição de `gameID` também recebe atualizações dos jogos filhos cujo `parentGameID` corresponda (p. ex., os derivados F5-MLB chegam aos subscritores do jogo pai).
- Os IDs de liga não distinguem maiúsculas de minúsculas — `mlb` e `MLB` são equivalentes.
- Os IDs de desporto não distinguem maiúsculas de minúsculas — `baseball` e `Baseball` são equivalentes.
- As cadeias vazias dentro dos arrays são ignoradas.
- `subscribe` com `replace: false` **e** todos os arrays vazios é um no-op (um cliente com bugs não consegue silenciar-se acidentalmente ao enviar um subscribe aditivo vazio).
- `subscribe` com `replace: true` **e** todos os arrays vazios é o caminho legítimo para «limpar todas as minhas subscrições» — a ligação entra em modo filtrado com zero subscrições e não recebe nada até subscrever de novo ou enviar `subscribeAll`.

## Mensagens {#messages}

Cada mensagem em `/price-stream` chega como um 2-tuplo `[type, payload]`. São difundidos três tipos de mensagens.

### `orderUpdate` {#orderupdate}

#### `orderUpdate` para mercados moneyline1x2 {#orderupdate-for-moneyline1x2-markets}

- `market` — o resultado a que o mercado diz respeito: um hex de ObjectID de participante (equipa da casa ou de fora) ou a cadeia literal `"draw"`.
- `side` — `"yes"` ou `"no"` sobre esse resultado.
- `OU`, `total` e `spread` estão ausentes, e `participantID` está vazio — use `market` + `side`.
