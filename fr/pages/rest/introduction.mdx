L'API REST 4casters vous permet de vous connecter, d'interroger les matchs et le carnet d'ordres, de placer / modifier / annuler des ordres et de lire votre historique de paris par programmation. C'est la même API qui alimente l'application web 4casters.

## URL de base {#base-url}

Tous les endpoints de cette section sont enracinés à :

```
https://api.4casters.io
```

## Conventions {#conventions}

- **Transport** : HTTPS uniquement.
- **Encodage** : JSON. Envoyez `Content-Type: application/json` sur chaque requête ayant un corps.
- **Enveloppe de réponse** : à quelques exceptions bien signalées près (`/affiliate/getAffiliateCommission`, `/exchange/getOddsForAveragePrice`), chaque réponse réussie est enveloppée : `{ "data": <payload> }`.
- **Identifiants** : les ids de match, de participant et d'ordre sont des chaînes `ObjectID` MongoDB (24 caractères hexadécimaux).
- **Cotes** : toutes les cotes sont au format américain (négatives pour les favoris, positives pour les outsiders) sauf mention contraire.
- **Temps** : tous les horodatages sont au format ISO 8601 avec `Z` (UTC).

## Authentification {#authentication}

Presque tous les endpoints exigent une authentification : un seul identifiant dans l'en-tête `Authorization`. Pour un programme, créez une [clé API](/fr/pages/rest/api-keys) sur la page de votre compte et envoyez-la. Sinon, connectez-vous une fois via [POST `/user/login`](/fr/pages/rest/authentication) et envoyez le token renvoyé. La [vue d'ensemble de l'authentification](/fr/pages/authentication) compare les deux.

## Erreurs par ordre vs erreurs HTTP {#per-order-errors-vs-http-errors}

Les endpoints « place » et « edit » acceptent des lots et renvoient des résultats par ordre. Une réponse HTTP `200` réussie peut quand même contenir des échecs d'ordres individuels dans `data.createdSessions[i]`. Voir le format d'erreur par ordre sur la page de chaque endpoint.

Les erreurs de niveau HTTP (`4xx`, `5xx`) sont renvoyées sous la forme `{ "error": "<message>" }`.

## Limitation de débit {#rate-limiting}

Voir [Limitation de débit](/fr/pages/rate-limiting).

## Timeouts {#timeouts}

Les requêtes qui prennent plus de **15 secondes** côté serveur sont interrompues et renvoient `503` avec le corps `{ "error": { "message": "Network Error", "code": 503 } }`.

## Mises à jour en temps réel {#real-time-updates}

L'API REST se combine avec l'[API WebSocket de streaming](/fr/pages/streaming/introduction) pour les ticks du carnet d'ordres en temps réel et les événements d'exécution / de règlement par compte. Le même identifiant, clé ou token, fonctionne pour les deux.
