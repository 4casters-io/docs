Dien één of meer orders in. Het endpoint accepteert een batch — de resultaten per order komen terug in `data.createdSessions`, **positioneel** ten opzichte van je invoerarray `orders`. Elke entry is ofwel een geslaagd `{ matched, unmatched }`-resultaat, ofwel een `{ error, errorType }`-mislukking.

## Verzoek {#request}

`POST /session/v3/place`

<CodeGroup>
```bash curl
curl -X POST https://api.4casters.io/session/v3/place \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "orders": [
      {
        "gameID": "688c0516fbc14da0c202d426",
        "type": "moneyline",
        "side": "5c12bc1ce0daba000f47ba8b",
        "odds": -175,
        "bet": 100,
        "orderType": "post",
        "userReference": "docs-example"
      }
    ]
  }'
```

```json JSON-body
{
  "orders": [
    {
      "gameID": "4CASTER_GAME_ID",
      "type": "moneyline | spread | total | moneyline1x2",
      "side": "PARTICIPANT_ID | over | under | yes | no",
      "market": "PARTICIPANT_ID | draw",
      "odds": -110,
      "bet": 100,
      "number": 3.5,
      "orderType": "limit | post | postArb | fillAndKill | fillOrKill",
      "expirationMinutes": 10,
      "userReference": "OPTIONAL_CLIENT_SIDE_IDENTIFIER"
    }
  ]
}
```
</CodeGroup>

## Ordertypen {#order-types}

### `limit` {#limit}

Het standaard-ordertype. Voert als taker uit tegen alle matchende liquiditeit op jouw prijs of beter (met taker-commissie) en zet de rest als maker in het boek. Een `limit`-order kan eindigen als volledig gematcht, volledig openstaand, of gedeeltelijk gematcht met de rest openstaand.

### `post` {#post}

Maak een openstaande offer aan. Als de order bij plaatsing tegen bestaande liquiditeit **zou matchen**, weigert de server hem (`rejected_order_type_rules`, bijv. `"post order cannot have matches"`).

### `postArb` {#postarb}

Gedraagt zich als `post`, maar je mag posten **ook wanneer de order zou matchen**, **alleen als** je Amerikaanse odds binnen **1%** liggen van de odds op de openstaande order waartegen je zou matchen. Is het prijsverschil meer dan 1%, dan wordt de plaatsing geweigerd.

Voorbeelden:

- Beste offer **+100** en jij post **+100** — `post` wordt geweigerd (hij zou matchen); `postArb` is toegestaan.
- Beste offer **+200** — `postArb` op **+190** wordt geweigerd (te ver van **+200**). Rond **+198** zit op de rand van de 1%-band t.o.v. **+200**.
- Beste order **−200** — de band loopt aan de negatieve kant tot ongeveer **−202** (dezelfde 1%-regel).
- Met **+100** in het boek is **−101** de referentiegrens aan de andere kant voor de 1%-tolerantie.

`postArb` vermijdt **taker-fees** over een normale trade — je betaalt op deze route geen taker-fees zoals je die wel zou betalen als je openstaande liquiditeit als taker zou wegnemen.

Orders geplaatst als `postArb` krijgen de vlag `isPostArb: true` op hun updates in de [user feed](/nl/pages/streaming/user-feed) en [price feed](/nl/pages/streaming/price-feed); voor andere ordertypen wordt het veld weggelaten. Het antwoord op de plaatsing zelf bevat de vlag niet.

### `fillAndKill` {#fillandkill}

Voer onmiddellijk als taker uit tegen de omvang die beschikbaar is op jouw prijs of beter, en annuleer de rest. Een `fillAndKill` blijft nooit in het boek staan.

Een **gedeeltelijke** fill is een geslaagd resultaat: stuur je `bet: 1000` terwijl er maar $400 aan matchbare liquiditeit bestaat, dan word je gevuld voor $400 en wordt de resterende $600 geannuleerd — het antwoord is een succes, geen fout. De order wordt alleen geweigerd (`rejected_order_type_rules`, `"fill and kill has no matches"`) wanneer er helemaal geen matchbare liquiditeit is. Zie de Fill And Kill-scenario's in de [voorbeelden](#examples) hieronder.

### `fillOrKill` {#fillorkill}

Alles of niets. Je **volledige** `bet` moet onmiddellijk matchen op jouw prijs of beter, anders wordt de hele order geweigerd — inclusief eventuele fills die onderweg gemaakt zijn; die worden teruggedraaid. Een `fillOrKill` blijft nooit in het boek staan, en je blijft nooit gedeeltelijk gevuld achter.

Gebruik dit wanneer een gedeeltelijke positie erger is dan geen positie, bijvoorbeeld wanneer de order één poot is van een hedge die je alleen volledig kunt uitvoeren.

Weigeringen dragen `errorType: rejected_order_type_rules` met één van twee meldingen, die "er was niets" onderscheiden van "er was niet genoeg":

- `"fill or kill has no matches"` — geen matchbare liquiditeit op jouw prijs.
- `"fill or kill matched but not fully"` — een deel van de liquiditeit matchte, maar niet je volledige omvang. Die fills zijn teruggedraaid.

<Note>
  Een restant van **$10 of minder** telt als volledig: een `fillOrKill` van $1,000 die $992 matcht, slaagt, omdat de $8 die niet gevuld kon worden onder de minimale omvang ligt die ooit in het boek zou kunnen staan. Een restant groter dan $10 laat de order weigeren.
</Note>

<CodeGroup>
```json Verzoek
{
  "orders": [
    {
      "gameID": "688c0516fbc14da0c202d426",
      "type": "moneyline",
      "side": "5c12bc1ce0daba000f47ba8b",
      "odds": -110,
      "bet": 1000,
      "orderType": "fillOrKill",
      "userReference": "docs-fillorkill-partial"
```

### Scenario 6 — `postArb` vs. `post` wanneer het boek zou matchen {#scenario-6--postarb-vs-post-when-the-book-would-match}

`post` weigert een order die tegen openstaande liquiditeit zou matchen (bijvoorbeeld: beste offer **+100** en jij probeert **+100** te posten). `postArb` staat die situatie toe wanneer jouw odds binnen **1%** liggen van de order waartegen je zou matchen — dezelfde **+100**-post kan dus slagen als `postArb`, en je vermijdt de taker-fees die je over een normale trade zou betalen. Ligt je prijs te ver van de openstaande notering (bijv. beste offer **+200** maar jij stuurt **+190**), dan wordt `postArb` geweigerd.

<CodeGroup>
```json Verzoek
{
  "orders": [
    {
      "gameID": "688c0516fbc14da0c202d426",
      "type": "moneyline",
      "side": "5c12bc1ce0daba000f47ba8b",
      "odds": 100,
      "bet": 50,
      "orderType": "postArb",
      "userReference": "docs-postarb-same-line-as-offer"
    }
  ]
}
```
</CodeGroup>

### Scenario 7 — `moneyline1x2` (driewegsmarkt voor voetbal) {#scenario-7--moneyline1x2-soccer-three-way}

`moneyline1x2` is de driewegsmarkt voor voetbal — thuis / uit / gelijkspel — geplaatst als een yes/no-weddenschap op de uitkomst die `market` benoemt. Hieronder: **yes op het gelijkspel** tegen +250.

<CodeGroup>
```json Verzoek
{
  "orders": [
    {
      "gameID": "65f0c3...",
      "type": "moneyline1x2",
      "side": "yes",
      "market": "draw",
      "odds": 250,
      "bet": 50,
      "orderType": "post",
      "userReference": "docs-ml1x2-yes-draw"
    }
  ]
}
```
</CodeGroup>

Om te wedden dat het **thuisteam niet wint**, stuur je `side: "no"` en zet je `market` op het id van de thuisdeelnemer.

## Live-vertraging {#live-delay}

Orders geplaatst op een wedstrijd die als live is gemarkeerd, volgen deze regels:

1. Als de order geen bestaande liquiditeit matcht, wordt hij onmiddellijk geplaatst.
2. Als de order wél bestaande liquiditeit matcht, geldt er een vertraging vóór uitvoering.
3. Verschillende competities hebben verschillende live-vertragingen:
    - **NFL, UFCMMA, NCAAF** — 3 seconden.
    - **NCAAB, NBA** — 5 seconden.
    - **ATP, WTA** — 8 seconden.
    - **Standaard** — 10 seconden.
4. Na de vertraging probeert de order uit te voeren:
    - Als de odds zijn verbeterd, matcht hij direct.
    - Als de odds zijn verslechterd, matcht hij niet.
