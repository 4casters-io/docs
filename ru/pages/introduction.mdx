4casters предоставляет три API, которые используют один и тот же token аутентификации и один и тот же движок аккаунтов / книги ордеров / расчётов. Выберите тот, который соответствует вашей задаче, или комбинируйте их — большинство интеграций используют REST для настройки и истории и WebSocket для торговли в реальном времени.

## Что и когда использовать {#when-to-use-which}

| Интерфейс | Лучше всего подходит для | Не используйте для |
| --- | --- | --- |
| **REST** (`https://api.4casters.io`) | Вход, информация об аккаунте, история ставок, поиск, просмотр рынков, пакетное размещение / изменение / отмена — всё, что вы запускали бы из скрипта или фоновой задачи. | Плотные внутренние циклы, где важна задержка кругового обхода. |
| **WebSocket ордеров** (`wss://orders-api.4casters.io/orders/ws`) | Живая торговля: размещение и отмена с низкой задержкой, постоянной сессией и корреляцией по `requestID`. | Чтение состояния — это канал записи/команд, а не API запросов. |
| **Стриминговый WebSocket** (`wss://streaming-api.4casters.io/...`) | Тики книги ордеров в реальном времени (фид цен) и события исполнения / расчёта по аккаунту (фид пользователя). | Одноразовые чтения — используйте REST вместо открытия потока. |

## Аутентификация {#authentication}

Все три API используют один token.

1. Вызовите [`POST /user/login`](/ru/pages/rest/authentication) в REST API со своими именем пользователя и паролем.
2. Отправляйте полученный token в каждом последующем запросе:
   - **REST**: заголовок `Authorization: Bearer <token>`.
   - **WebSocket**: заголовок `Authorization: <token>` при рукопожатии.

Token действителен 30 дней и может быть обновлён до истечения срока. См. [Аутентификация](/ru/pages/rest/authentication) — обновление token, аутентификация подписанными cookie и подробности.

## Соглашения {#conventions}

- **Транспорт**: только HTTPS / WSS.
- **Кодирование**: везде JSON.
- **Конверт ответа (REST)**: `{ "data": <payload> }` при успехе; `{ "error": "<message>" }` при HTTP-ошибках.
- **Идентификаторы**: id игр, участников и ордеров — строки MongoDB `ObjectID` (24 шестнадцатеричных символа).
- **Коэффициенты**: американский формат (отрицательные для фаворитов, положительные для андердогов), если не указано иное.
- **Время**: ISO 8601 с `Z` (UTC).

## Типичная интеграция {#a-typical-integration}

Большинство нетривиальных клиентов комбинируют все три API:

1. **REST** — один раз выполните `POST /user/login`, закешируйте token, затем вызовите `GET /user/getMe` и `GET /games/v2/leagues` для начальной загрузки состояния.
2. **Стриминговый WebSocket** — откройте фид цен для интересующих вас рынков и фид пользователя, чтобы реагировать на собственные исполнения / расчёты.
3. **WebSocket ордеров** — откройте постоянное соединение и размещайте / отменяйте ордера с низкой задержкой, сопоставляя ответы по `requestID`.
4. **REST** — обращайтесь к `POST /myBets/getMatchedBets`, `/myBets/getOrdersForGame` и т. д. для истории и сверки.
