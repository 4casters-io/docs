比分推送透過原始 WebSocket 連線以 JSON 訊息投遞即時的賽事狀態 — 比分、節次、比賽時鐘，以及對各個運動項目而言關鍵的那部分細節。

<CodeGroup>
```javascript JavaScript
// score_feed_quickstart.js
const WebSocket = require('ws');
const token = process.env.FOURCASTERS_TOKEN;

function connectScoreFeed() {
  const ws = new WebSocket('wss://streaming-api.4casters.io/v1/score', {
    headers: { Authorization: token },
  });

  let pingTimer; let lastPong = Date.now();

  ws.on('open', () => {
    console.log('score feed connected');

    // REQUIRED. A connection starts with no subscriptions and receives
    // nothing until it asks: there is no "everything" default on this feed.
    ws.send(JSON.stringify({
      type: 'subscribe',
      gameIDs: [],
      leagueIDs: ['NBA'],
      sportIDs: [],
      replace: true,
    }));

    pingTimer = setInterval(() => {
      if (ws.readyState === WebSocket.OPEN) ws.ping();
      if (Date.now() - lastPong > 30000) {
        console.warn('score feed: missed pong >30s, closing');
        ws.terminate();
      }
    }, 10000);
  });

  ws.on('pong', () => { lastPong = Date.now(); });

  ws.on('message', (buf) => {
    try {
      const [type, payload] = JSON.parse(buf.toString());
      if (type !== 'gameState') return; // ignore types you don't know
      console.log('game state:', JSON.stringify(payload, null, 2));
    } catch { console.log('score feed (raw):', buf.toString()); }
  });

  ws.on('error', (e) => console.error('score feed error:', e.message));

  ws.on('close', (code, reason) => {
    console.log(`score feed closed: ${code} ${reason}`);
    clearInterval(pingTimer);
    setTimeout(connectScoreFeed, 1000);
  });
}
connectScoreFeed();
```
</CodeGroup>

## Ping/Pong {#pingpong}

比分推送支援標準 WebSocket `ping/pong`。你可以按間隔主動呼叫 `ping()`，並透過跟蹤 `pong` 來確認連線存活。

伺服器也會傳送 ping，大約每 25 秒一次；若一個連線有兩次 ping 未回應，伺服器會以關閉碼 `4002`（`pong timeout`）關閉它。標準 WebSocket 用戶端會自動回應 ping。

**訊息到達後請及時讀取。** pong 會排在你尚未讀取的訊息之後，因此讀取速度慢於推送傳送速度的用戶端，可能錯過它自己的 30 秒 pong 期限，從而反覆重連。請把耗時的處理放在套接字的讀取路徑之外。

## 連線限制與關閉碼 {#connection-limits-and-close-codes}

每個帳戶同時開啟的比分推送連線請不要超過 **20** 個。超過之後，新的連線會在 WebSocket 升級之前被 HTTP `429` 拒絕。

| 情況 | 你會收到 | 應對方式 |
| --- | --- | --- |
| 沒有有效的 token | 升級之前回傳 HTTP `401` | 先修正 token 再重試 |
| 你的帳戶連線過多 | 升級之前回傳 HTTP `429` | 關閉不再使用的連線 |
| 伺服器正在關閉 | 升級之前回傳 HTTP `503` | 稍等片刻後重連 |
| 部署關閉了你的連線 | 關閉碼 `1001` | 重新連線；你會收到一份新的快照 |
| 你的會話已結束（登出或被撤銷） | 關閉碼 `1008`，原因 `session revoked` | 重新登入後再連線 |
| 有兩次伺服器 ping 未回應 | 關閉碼 `4002`，原因 `pong timeout` | 重新連線，並及時讀取訊息 |
| 你傳送的訊息超過 64 KiB | 關閉碼 `1009`（訊息過大） | 每則命令保持在 64 KiB 以內，約可容納 2,400 個 `gameIDs` |

## 連線時的快照 {#snapshot-on-connect}

當你訂閱時，推送會傳送你的訂閱所涵蓋的每一場進行中賽事的當前狀態。每條快照訊息都帶有 `"snapshot": true`。

之所以有這份快照，是因為該推送發布的是**變化**，而不是心跳。若沒有快照，在中場休息時連上的用戶端在某場賽事下一次發生變化之前對它一無所知 — 而這可能是好幾分鐘。

新建立的連線沒有任何訂閱，因此請**先訂閱**：真正有用的快照是帶 `replace: true` 的訂閱命令所回傳的那一份。訂閱某個聯賽看板，其當前狀態會立即到達。

- 快照訊息與即時訊息使用相同的 `[type, payload]` 結構，唯一的區別是 `snapshot` 標誌。
- 已經結束的賽事不包含在內。
- 快照之後，即時更新在同一個套接字上繼續到達。沒有單獨的「快照完成」訊息：無論訊息是否帶有該標誌，都按同樣的方式處理。
- 若你重新連線，會收到一份新的快照。從它重建狀態是從斷線中恢復的受支援方式。
- **快照通常先於即時更新到達，但它既不是屏障，也不是看板重置。**
    - 如果你重新訂閱的速度超過[快照節奏](#subscribe-by-gameid-league-or-sport)所允許的範圍，新看板的即時更新可能先於其快照到達。
    - 某場賽事的快照訊息可能被同一賽事更新的即時訊息取代，因此這場賽事可能永遠不會以帶標誌的形式到達。
    - 部署剛完成時，如果伺服器尚未載入完狀態，快照可能是不完整的，而且不會有任何提示。

  按照[以最新為準](#pitfalls)的規則處理每一條訊息，以上任何一種情況都不會讓你的看板出錯。

## 訂閱 {#subscriptions}

**連線建立後沒有任何訂閱，在主動請求之前不會收到任何訊息。**請在套接字進入 `open` 後，以 JSON 文字幀傳送下列命令之一；命令在該連線的生命週期內生效。

<Warning>
沒有任何方式可以訂閱全部賽事。請只訂閱你正在展示的內容 —— 一個聯賽看板、一個滾球標籤頁，或單場賽事。連線後從不訂閱的用戶端收不到任何訊息，這是預期行為，而不是推送失效。
</Warning>

訂閱使用與 [行情推送](/zh-Hant/pages/streaming/price-feed#subscriptions) 相同的命令和相同的鍵，因此已經對接該推送的用戶端無需掌握任何新概念；但若你用過那個推送，有一處差異值得注意：它預設廣播全部內容而本推送不會，它有 `subscribeAll` 這個 catch-all 而本推送沒有。

### 按 gameID、聯賽或運動項目訂閱 {#subscribe-by-gameid-league-or-sport}

安裝過濾器。`gameIDs` 為 24 位 Mongo ObjectID 十六進位字串；`leagueIDs` 為短代碼，如 `NBA` / `MLB` / `EPL`；`sportIDs` 為小寫識別碼，如 `basketball` / `baseball` / `soccer`。

<CodeGroup>
```json 替換（推薦）
{
  "type": "subscribe",
  "gameIDs": ["62619dce25e2fb049a71cc2e"],
  "leagueIDs": ["NBA"],
  "sportIDs": [],
  "replace": true
}
```
```json 追加
{
  "type": "subscribe",
  "gameIDs": [],
  "leagueIDs": ["MLB"],
  "sportIDs": [],
  "replace": false
}
```
</CodeGroup>

- `replace: true` 清除該連線上任何現有訂閱，並安裝新列表。
- `replace: false` 將新鍵追加到該連線已訂閱的集合中。

帶 `replace: true` 的 subscribe 還會為你剛剛訂閱的賽事觸發一份新的快照，因此收窄推送會立即填滿你新的卡片，而不必等到它們下一次發生變化。

**快照有節奏限制**，按連線計算：最多同時三份，之後每秒一份。超出這一額度的 `replace: true` 訂閱不會被拒絕或丟棄。它的快照會被推遲，傳送時按你當時的訂閱內容生成。

### 取消訂閱 {#unsubscribe}

移除指定鍵。剩下的鍵就是該連線仍會收到的內容；移除最後一個鍵後，它將不再收到任何訊息。

<CodeGroup>
```json JSON
{
  "type": "unsubscribe",
  "gameIDs": [],
  "leagueIDs": ["MLB"],
  "sportIDs": []
}
```
</CodeGroup>

### 路由語義 {#routing-semantics}

- 訂閱某個 `gameID` 時，也會收到任何 `parentGameID` 與之匹配的賽事更新。賽事的滾球市場會發布自己的狀態（參見[子市場](#child-markets)），因此訂閱一場賽事的 `gameID` 也會收到其滾球市場的訊息。
- 聯賽 ID 不區分大小寫 — `mlb` 與 `MLB` 等價。
- 運動項目 ID 不區分大小寫 — `baseball` 與 `Baseball` 等價。
- 陣列中的空字串會被忽略。
- `subscribe` 在 `replace: false` **且** 陣列全部為空時為無操作。
- `subscribe` 在 `replace: true` **且** 陣列全部為空時，是「清除我的全部訂閱」路徑 — 連線的訂閱歸零，在你再次訂閱之前不會收到任何訊息。
- `subscribeAll` 在本推送中**不是**命令。傳送它不會有任何效果，也不會得到確認。

## 訊息 {#messages}

`/v1/score` 上的每條訊息都以二元組 `[type, payload]` 到達。

**忽略你不認識的訊息型別。**該推送會在不改變版本的情況下新增訊息型別；假定型別集合固定的用戶端在新型別到來時會出錯。請對 `type` 做分支判斷，並跳過預設分支。

### `gameState` {#gamestate}

賽事的觀測狀態發生變化時發出。每場賽事每次變化一條訊息 — 推送不會重複傳送未發生變化的狀態，因此一場安靜的賽事是正常的，並不表示連線已失效。

如果你的連線跟不上，推送會傳送每場賽事的最新狀態，而不是每一箇中間狀態：仍在等待傳送的訊息會被同一賽事更新的訊息取代。

<CodeGroup>
```json JSON
[
  "gameState",
  {
    "gameID": "62619dce25e2fb049a71cc2e",
    "parentGameID": null,
    "league": "NBA",
    "sport": "basketball",
    "status": "LIVE",
    "detail": "6:12 - 3rd",
    "period": 3,
    "clock": "6:12",
    "clockSeconds": 372,
    "homeScore": 78,
    "awayScore": 71,
    "stoppage": null,
    "ts": 1791830400000
  }
]
```
</CodeGroup>

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `gameID` | string | 24 位 ObjectID 十六進位 |
| `parentGameID` | string 或 null | 賽事自身的訊息中為 `null`；滾球市場的訊息中為父賽事的 `gameID`（參見[子市場](#child-markets)） |
| `league` | string | 短代碼，如 `NBA` |
| `sport` | string | 小寫識別碼，如 `basketball` |
| `status` | string | 見下文 |
| `detail` | string 或 null | 記分牌自身給出的那行文字，如 `"Bot 7th"`、`"6:12 - 3rd"` |
| `period` | integer 或 null | 節、局、小節或半場 |
| `clock` | string 或 null | 按顯示值給出 |
| `clockSeconds` | integer 或 null | 同一時鐘的秒數形式，便於做計算 |
| `homeScore` | integer 或 null | |
| `awayScore` | integer 或 null | |
| `stoppage` | object 或 null | `{ "type": …, "team": …, "since": … }`；`since` 是**自 epoch 起的毫秒數**，與 `ts` 相同；當資料來源未提供時該欄位被省略 |

| `snapshot` | boolean | 僅在快照訊息上出現，且恆為 `true` |

`status` 為 `SCHEDULED`、`LIVE`、`HALFTIME`、`END_PERIOD`、`DELAYED`、`SUSPENDED`、`FINAL`、`CANCELLED`、`POSTPONED`、`UNKNOWN` 之一。遇到不認識的狀態，請當作 `UNKNOWN` 處理，而不要丟棄該訊息 — 其中的比分和時鐘仍然可用。

## 子市場 {#child-markets}

一場賽事的滾球市場、上半場和下半場在我們的系統中是各自獨立的賽事，各有自己的 `gameID` 和自己的聯賽 ID —— `NBA-LIVE`、`NFL-1H`、`NBA-2H`。

**滾球市場會發布狀態。**父賽事發布的每一個狀態都會在滾球市場下再發布一次，使用滾球市場自己的 `gameID` 和聯賽（`NBA-LIVE`），並且 `parentGameID` 為父賽事的 `gameID`。比分、時鐘和節次都是父賽事的。

**上半場、下半場和 props 市場不發布任何內容。**訂閱它們的 `gameID` 或聯賽 ID 將完全收不到任何訊息 —— 而"收不到任何訊息"正是一場平靜賽事的表現。

要在任何子市場旁顯示比分，請訂閱其**父賽事**：父賽事的 `gameID`，或父聯賽（`NBA`，而不是 `NBA-LIVE`）。在子市場的卡片上顯示父賽事的狀態。這適用於所有型別的子市場。

<Warning>
訂閱 `NFL-1H`、`NBA-2H` 或其他半場或 props 聯賽 ID 都會被靜默接受，但不會收到任何訊息。請使用父聯賽 ID。
</Warning>

## 常見陷阱 {#pitfalls}

**缺失意味著未知，絕不等於零。**推送無法確定的欄位會被省略或為 null — 絕不會以 `0` 的形式下發。這一點在棒球的球數上最為關鍵：`balls`、`strikes` 和 `outs` 要麼一起到達，要麼都不到達，因此缺失的球數絕不能渲染成 `"0-0, 0 out"`。請把 `null` 與欄位缺失同等對待。

**安靜的賽事不等於推送已死。**該推送發布的是變化。雨天延誤、中場休息或比賽中斷期間完全不會產生訊息，有時會持續好幾分鐘。不要把「最近沒有訊息」當作某場賽事的存活判據 — 連線用 `ping`/`pong` 判斷，賽事用 `status` 判斷。

**賽事自身的訊息中 `parentGameID` 為 `null`。**只有滾球市場的訊息才帶有值，即父賽事的 `gameID`（參見[子市場](#child-markets)）。訂閱父賽事的 `gameID` 會同時收到兩者，它們在兩個不同的 `gameID` 下攜帶相同的狀態，因此請按你所顯示的 `gameID` 來組織看板。

**比分是整數，不是字串。**與行情推送上的某些欄位不同，`homeScore` 和 `awayScore` 是 JSON 數字。

**最新者優先。**應用一條訊息之前先比較 `ts`。跨重連不保證順序，而快照也可能與即時幀交錯到達 — 比你已持有的狀態更舊的幀應當丟棄，而不是應用。

**不要自行推算時鐘。**`clock` 是記分牌顯示的值，只在資料提供方發布新值時才變化，頻率大約是每次進攻一次，而不是每秒一次。在兩條訊息之間本地倒計時會產生偏差，並且在比賽暫停時一定是錯的。
