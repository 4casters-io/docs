Todas las APIs de 4casters, REST y WebSocket por igual, se autentican de la misma forma: una credencial en el encabezado `Authorization`. Hay dos tipos de credencial, y la única decisión es cuál usar.

| | Clave de API | Token de inicio de sesión |
| --- | --- | --- |
| **Pensada para** | Programas: bots, scripts, tareas de backend. | El sitio web y cualquier cosa de corta duración. |
| **Cómo se obtiene** | Una vez, desde la página de tu cuenta. | `POST /user/login` con tu nombre de usuario y contraseña. |
| **Vida útil** | Hasta que la revoques, o la caducidad que elegiste al crearla. | 30 días; después se rota en el lugar en la siguiente solicitud. |
| **Restricción de red** | Por clave: direcciones o rangos CIDR IPv4 e IPv6. | Ninguna (puede acordarse una lista blanca para toda la cuenta a través de soporte). |
| **Revocación** | Por clave, instantánea, desde la página de la cuenta. | Cerrar sesión, o un cambio de contraseña, revoca todos los tokens de inicio de sesión. |
| **Puede administrar la cuenta** | No. La administración de la cuenta (claves, contraseña, 2FA, retiros) requiere una sesión en el sitio web. | Sí. |

**Si escribes código que se ejecuta sin supervisión, usa una clave de API.** Los tokens de inicio de sesión existen para que el sitio web pueda iniciar tu sesión; rotan, mueren con un cambio de contraseña y uno filtrado vale tanto como tu contraseña hasta que lo notes.

## Claves de API {#api-keys}

Crea una en **Mi cuenta → Seguridad → API Keys** (o ve directamente a [4casters.io/account/api-keys](https://4casters.io/account/api-keys)): dale un nombre, restríngela opcionalmente a los rangos de IP de tus servidores y dale una caducidad, y copia la clave de la confirmación. Se muestra una sola vez.

Una clave tiene esta forma: `4ck_Wk15VXFX_T4MPcp8Ij2IODI7OFFIlQsHmvvzJ3Nj8C-StfVe3h0k`. La primera parte, `4ck_Wk15VXFX`, es su **Key ID**: no es secreta, y es como la página de la cuenta se refiere a la clave. El resto es el secreto.

Envíala exactamente donde iría un token de inicio de sesión:

<Tabs>
  <Tab title="API REST">
    ```bash
    curl https://api.4casters.io/user/getMe \
      -H "Authorization: 4ck_Wk15VXFX_T4MPcp8Ij2IODI7OFFIlQsHmvvzJ3Nj8C-StfVe3h0k"
    ```
  </Tab>
  <Tab title="WebSocket de órdenes">
    ```javascript
    const ws = new WebSocket('wss://orders-api.4casters.io/orders/ws', {
      headers: { Authorization: process.env.FOURCASTERS_API_KEY },
    });
    ```
  </Tab>
  <Tab title="WebSocket de streaming">
    ```javascript
    const ws = new WebSocket('wss://streaming-api.4casters.io/v2/user', {
      headers: { Authorization: process.env.FOURCASTERS_API_KEY },
    });
    ```
  </Tab>
</Tabs>

No hay paso de inicio de sesión ni nada que renovar. La referencia completa, con IPs permitidas, caducidad, lo que una clave no puede hacer y todos los errores que puede producir, está en la [página de claves de API](/es/pages/rest/api-keys).

## Tokens de inicio de sesión {#login-tokens}

Un token de inicio de sesión es lo que el sitio web conserva después de que inicias sesión. Funciona en todas las APIs, así que sirve para un experimento rápido o un script puntual; para cualquier cosa que siga ejecutándose, prefiere una clave.

### 1. Iniciar sesión {#1-log-in}

`POST https://api.4casters.io/user/login`

<CodeGroup>
```bash curl
curl -X POST https://api.4casters.io/user/login \
  -H "Content-Type: application/json" \
  -d '{"username": "your_username", "password": "your_password"}'
```

```javascript JavaScript
const res = await fetch('https://api.4casters.io/user/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    username: process.env.FOURCASTERS_USERNAME,
    password: process.env.FOURCASTERS_PASSWORD,
  }),
});
const { data } = await res.json();
const token = data.user.auth;
```

```python Python
import os, requests

res = requests.post(
    "https://api.4casters.io/user/login",
    json={
        "username": os.environ["FOURCASTERS_USERNAME"],
        "password": os.environ["FOURCASTERS_PASSWORD"],
    },
    headers={"User-Agent": "my-bot/1.0"},
)
token = res.json()["data"]["user"]["auth"]
```
</CodeGroup>

El campo `username` acepta tanto tu nombre de usuario como el email de la cuenta.

El token está en `data.user.auth` en el cuerpo de la respuesta: una cadena hexadecimal de 256 caracteres. El mismo valor también se establece como cookie `auth` firmada; las integraciones del lado del servidor deben capturar `data.user.auth` e ignorar la cookie.

```json
{
  "data": {
    "user": {
      "id": "5fe37acbb5a23600123662c1",
      "username": "your_username",
      "auth": "5cd551d6...",
      "...": "..."
    }
  }
}
```

La forma completa de la respuesta está documentada en la [página de inicio de sesión REST](/es/pages/rest/authentication).

<Tip>
Inicia sesión **una vez** y reutiliza el token. El inicio de sesión tiene límite de tasa por IP y por cuenta, y cada inicio de sesión exitoso emite un token nuevo. Volver a iniciar sesión no invalida los tokens que ya tienes.
</Tip>

### 2. Enviar el token {#2-send-the-token}

<Tabs>
  <Tab title="API REST">
    Pasa el token en el encabezado `Authorization`. El prefijo `Bearer ` es opcional.

    ```bash
    curl https://api.4casters.io/user/getMe \
      -H "Authorization: Bearer 5cd551d6..."
    ```

    Un token ausente, desconocido o expirado devuelve `401` con el cuerpo `{ "error": { "message": "InvalidCredentials", "code": 401 } }`.
  </Tab>
  <Tab title="WebSocket de órdenes">
    Pasa el token en el encabezado `Authorization` del handshake. El servidor deriva tu cuenta a partir del token.

    ```javascript
    const ws = new WebSocket('wss://orders-api.4casters.io/orders/ws', {
      headers: { Authorization: token },
    });
    ```

    Consulta la [API de órdenes](/es/pages/websocket/introduction).
  </Tab>
  <Tab title="WebSocket de streaming">
    Mismo encabezado, mismo token, tanto para el feed de usuario como para el feed de precios.

    ```javascript
    const ws = new WebSocket('wss://streaming-api.4casters.io/v2/user', {
      headers: { Authorization: token },
    });
    ```

    Consulta la [API de streaming](/es/pages/streaming/introduction).
  </Tab>
</Tabs>

### Vida útil del token {#token-lifetime}

| | |
| --- | --- |
| **Válido durante** | 30 días desde el inicio de sesión. |
| **Después de 30 días** | La siguiente solicitud REST autenticada rota el token en el lugar: el valor antiguo deja de funcionar de inmediato y el reemplazo se devuelve en el encabezado de respuesta `X-Auth-Token`. |
| **Cerrar sesión** | `POST /user/logout` invalida el token usado en esa llamada. Los demás tokens de la cuenta no se ven afectados. |
| **Cambio de contraseña** | Invalida todos los tokens de inicio de sesión de la cuenta. Las claves de API no se ven afectadas. |

Si tienes que funcionar con un token de inicio de sesión durante más de un mes, haz una de estas dos cosas:

- **Vuelve a iniciar sesión ante cualquier `401`.** Lo más simple y robusto. Trata el `401` como "consigue un token nuevo", no como un error fatal.
- **Vigila `X-Auth-Token`.** Siempre que ese encabezado aparezca en una respuesta, guarda su valor y úsalo a partir de entonces.

Un script que inicia sesión una vez, guarda el token y nunca mira los encabezados de respuesta funcionará exactamente 30 días y luego fallará con `401` en todas las solicitudes. Una clave de API no tiene nada de esto.

### Errores de inicio de sesión {#login-errors}

| Estado | Significado | Qué hacer |
| --- | --- | --- |
| `400` | Falta `username` o `password` en el cuerpo. | Envía ambos como JSON. |
| `401` | El nombre de usuario o la contraseña son incorrectos. | Revisa las credenciales. El mensaje es el mismo exista o no la cuenta. |
| `403` | Cuenta baneada, cerrada o congelada. | Contacta con soporte. |
| `428` | `CHALLENGE_REQUIRED`. Solo se devuelve mientras la plataforma mitiga activamente un ataque de credential stuffing; se exige un desafío de verificación humana. | Sigue usando una credencial que ya tengas, o espera y reintenta. Los clientes automatizados no pueden resolver el desafío. Una clave de API nunca recibe el desafío. |
| `429` | Límite de tasa de inicio de sesión superado. | Espera los segundos de `Retry-After` y reutiliza los tokens existentes en lugar de volver a iniciar sesión. |

## Autenticación de dos factores {#two-factor-authentication}

La autenticación de dos factores en 4casters protege los **retiros**, no el inicio de sesión. Activarla en tu cuenta no cambia cómo te autenticas contra la API: `POST /user/login` nunca pide un código, y las claves de API no se ven afectadas.

## Proteger las credenciales {#keeping-credentials-safe}

- Guarda claves, nombres de usuario y contraseñas en variables de entorno o en un gestor de secretos, nunca en el control de versiones.
- Trata una clave o un token como una contraseña. Cualquiera que lo tenga puede colocar órdenes y leer tu cuenta.
- Dale a cada programa su propia clave de API, con el nombre del programa, y restríngela a las direcciones desde las que se ejecuta. Si una se filtra, revoca esa.
- Considera una cuenta dedicada para el trading automatizado, de modo que una credencial filtrada no exponga tu saldo principal. Las cuentas se abren igual que cualquier cuenta de usuario.
