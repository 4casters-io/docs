Quando o servidor falha uma ordem individual em um lote de envio, edição ou cancelamento por ordem, a entrada **por ordem** é retornada assim:

```json
{
  "error": "<human-readable message>",
  "errorType": "validation_error | rejected_liability | rejected_order_type_rules | system_error"
}
```

Os erros são retornados **por posição** no array de resultados, correspondendo ao índice da ordem de entrada. Se você receber um erro para uma ordem, essa ordem não foi processada e é seguro tentar novamente.

- `error` não é padronizado — é uma string descritiva e pode mudar.
- `errorType` é um enum estável no qual você pode confiar para o tratamento programático:
  - `validation_error` — o payload ou o estado não passaram na validação (campos faltando, odds/número inválidos, `side` inválido, evento inativo).
  - `rejected_liability` — restrições de usuário / conta / exposição impediram o envio ou a execução.
  - `rejected_order_type_rules` — as regras do tipo de ordem proibiram a execução. Exemplos: `fillAndKill` não tinha liquidez executável, `fillOrKill` não pôde ser casada por completo, `post` casaria com ordens em aberto, ou `postArb` está a mais de 1% do preço casável.
  - `system_error` — erro interno transitório; uma nova tentativa pode funcionar.
