Quando o servidor falha uma ordem individual em um lote de envio, edição ou cancelamento por ordem, a entrada **por ordem** é retornada assim:

```json
{
  "error": "<human-readable message>",
  "errorType": "validation_error | rejected_liability | rejected_order_type_rules | system_error"
}
```

Os erros são retornados **posicionalmente** no array de resultados, correspondendo ao índice da ordem de entrada. Se você recebeu um erro para uma ordem, essa ordem não foi processada e pode ser reenviada com segurança.

- `error` não é padronizado — é uma string descritiva e pode mudar.
- `errorType` é um enum estável no qual você pode se apoiar para tratamento programático:
  - `validation_error` — o payload ou o estado falhou na validação (campos faltando, odds/number inválidos, side inválido, jogo inativo).
  - `rejected_liability` — restrições de usuário / conta / responsabilidade impediram a postagem ou a execução.
  - `rejected_order_type_rules` — as regras do tipo de ordem proibiram a execução. Exemplos: `fillAndKill` não tinha liquidez executável, `fillOrKill` não pôde ser correspondida por completo, `post` corresponderia a ordens em espera, ou `postArb` está a mais de 1% do preço correspondível.
  - `system_error` — erro interno transitório; uma nova tentativa pode ter sucesso.
