---
title: 'API de ordens da 4casters'
---

A API de ordens da 4casters permite enviar e cancelar ordens em tempo real e gerenciar a sessão por uma conexão WebSocket crua.

## Endpoints {#endpoints}
- **API de ordens**: `wss://orders-api.4casters.io/orders/ws`

## Autenticação {#auth}

A conexão se autentica com um token da 4Casters. Envie o token no
cabeçalho `Authorization` do handshake WebSocket. O servidor deriva o usuário
a partir do token: **sem nome de usuário na URL**.

### Obter um token {#get-a-token}

Não há uma chave de API separada. Faça login com seu nome de usuário e senha
da 4Casters chamando o endpoint `/user/login` da API REST da 4Casters. A resposta
inclui um token que você pode usar aqui. Consulte [Autenticação](/pt-BR/pages/authentication)
para o tempo de vida e a rotação do token.

Consulte [`POST /user/login` na documentação da API REST da 4Casters](/pt-BR/pages/rest/authentication).

### Conectar {#connect}

<CodeGroup>
```javascript JavaScript
const WebSocket = require('ws');
const token = process.env.FOURCASTERS_TOKEN;
const ws = new WebSocket('wss://orders-api.4casters.io/orders/ws', {
  headers: { Authorization: token },
});
```
</CodeGroup>

## Formato de mensagens {#message-format}

Cada requisição do cliente é uma 2-tupla `[messageType, payload]`. Cada payload deve incluir um `requestID` que você gera; o servidor o retorna para que você possa correlacionar as respostas.

<CodeGroup>
```json Requisição
[
  "messageType",
  {
    "requestID": "YOUR_REQUEST_ID",
    "...": "..."
  }
]
```
</CodeGroup>

As respostas do servidor são objetos JSON com `requestID` mais `data` (sucesso) ou `error` (falha):

<CodeGroup>
```json Sucesso
{
  "requestID": "YOUR_REQUEST_ID",
  "data": { "...": "..." }
}
```

```json Erro
{
  "requestID": "YOUR_REQUEST_ID",
  "error": "human-readable error"
}
```
</CodeGroup>
