O feed de preços transmite atualizações de mercado/livro de ofertas como mensagens JSON por uma conexão WebSocket pura.

<CodeGroup>
```javascript JavaScript
// price_feed_quickstart.js 
const WebSocket = require('ws'); 
const token = process.env.FOURCASTERS_TOKEN; 
 
function connectPriceFeed() { 
  const ws = new 
  WebSocket('wss://streaming-api.4casters.io/price-stream', { 
    headers: { Authorization: token }, 
  }); 
 
  let pingTimer; let lastPong = Date.now(); 
 
  ws.on('open', () => { 
    console.log('price stream connected'); 

    // Optional: narrow the feed to specific games / leagues / sports.
    // Omit this block to receive all market updates (default). 
    ws.send(JSON.stringify({ 
      type: 'subscribe', 
      gameIDs: [], 
      leagueIDs: ['NBA'], 
      sportIDs: [], 
      replace: true, 
    })); 

    pingTimer = setInterval(() => { 
      if (ws.readyState === WebSocket.OPEN) ws.ping(); 
      if (Date.now() - lastPong > 30000) { 
        console.warn('price stream: missed pong >30s, closing'); 
        ws.terminate(); 
      } 
    }, 10000); 
  }); 
 
  ws.on('pong', () => { lastPong = Date.now(); }); 
 
  ws.on('message', (buf) => { 
    try { 
      const msg = JSON.parse(buf.toString()); 
      console.log('price update:', JSON.stringify(msg, null, 2)); 
    } catch { console.log('price update (raw):', buf.toString()); } 
  }); 
 
  ws.on('error', (e) => console.error('price stream error:', e.message)); 
 
  ws.on('close', (code, reason) => { 
    console.log(`price stream closed: ${code} ${reason}`); 
    clearInterval(pingTimer); 
    setTimeout(connectPriceFeed, 1000); 
  }); 
} 
connectPriceFeed();
```
</CodeGroup>

## Ping/Pong {#pingpong}
Ambos os feeds suportam o `ping/pong` padrão do WebSocket. Você pode fazer `ping()` proativamente em um intervalo e acompanhar o `pong` para verificar se a conexão está viva.

## Assinaturas {#subscriptions}

Por padrão, um cliente conectado recebe toda atualização de mercado de todos os esportes e ligas. Para restringir esse volume, envie um dos comandos a seguir como um frame de texto JSON depois que o socket estiver `open`. Os comandos valem pela vida útil da conexão.

Um cliente que nunca envia um comando de assinatura permanece no modo de difusão total, então as integrações existentes continuam funcionando sem mudanças.

### Assinar por gameID, liga ou esporte {#subscribe-by-gameid-league-or-sport}

Instale um filtro. `gameIDs` são strings hex de ObjectID do Mongo com 24 caracteres; `leagueIDs` são códigos curtos como `NBA` / `MLB` / `EPL`; `sportIDs` são tokens em minúsculas como `basketball` / `baseball` / `soccer`.

<CodeGroup>
```json Substituir (recomendado)
{
  "type": "subscribe",
  "gameIDs": ["62619dce25e2fb049a71cc2e"],
  "leagueIDs": ["NBA"],
  "sportIDs": [],
  "replace": true
}
```
```json Aditivo
{
  "type": "subscribe",
  "gameIDs": [],
  "leagueIDs": ["MLB"],
  "sportIDs": [],
  "replace": false
}
```
</CodeGroup>

- `replace: true` limpa quaisquer assinaturas existentes nesta conexão e instala as novas listas. Muda a conexão para o modo filtrado.
- `replace: false` adiciona as novas chaves ao que a conexão já assina.

Você receberá uma atualização se o `gameID`, `parentGameID`, `league` ou `sport` dela corresponder a qualquer uma das suas assinaturas.

### Cancelar assinatura {#unsubscribe}

Remova chaves específicas. A conexão permanece no seu modo atual (filtrado ou assinar-tudo).

<CodeGroup>
```json JSON
{
  "type": "unsubscribe",
  "gameIDs": [],
  "leagueIDs": ["MLB"],
  "sportIDs": []
}
```
</CodeGroup>

### Assinar tudo {#subscribe-to-everything}

Um "pega-tudo" explícito. Útil se você restringiu antes via `subscribe` e quer voltar a ampliar sem reconectar. Limpa quaisquer assinaturas por chave na conexão.

<CodeGroup>
```json JSON
{ "type": "subscribeAll" }
```
</CodeGroup>

### Semântica de roteamento {#routing-semantics}

- Uma assinatura de `gameID` também recebe atualizações de jogos filhos cujo `parentGameID` corresponde (ex.: derivativos F5-MLB chegam aos assinantes do jogo pai).
- IDs de liga não diferenciam maiúsculas de minúsculas — `mlb` e `MLB` são equivalentes.
- IDs de esporte não diferenciam maiúsculas de minúsculas — `baseball` e `Baseball` são equivalentes.
- Strings vazias dentro dos arrays são ignoradas.
- `subscribe` com `replace: false` **e** todos os arrays vazios é um no-op (um cliente com bug não consegue se silenciar acidentalmente enviando um subscribe aditivo vazio).
- `subscribe` com `replace: true` **e** todos os arrays vazios é o caminho legítimo de "limpar todas as minhas assinaturas" — a conexão entra no modo filtrado com zero assinaturas e não recebe nada até você assinar de novo ou enviar `subscribeAll`.

## Mensagens {#messages}

Toda mensagem em `/price-stream` chega como uma 2-tupla `[type, payload]`. Três tipos de mensagem são transmitidos.

- `market` — o resultado ao qual o mercado se refere: um hex de ObjectID de participante (time da casa ou visitante) ou a string literal `"draw"`.

- `OU`, `total` e `spread` estão ausentes, e `participantID` está vazio — use `market` + `side`.
