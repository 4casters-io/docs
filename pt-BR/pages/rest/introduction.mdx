A API REST da 4casters permite que você faça login, consulte eventos e o livro de ordens, envie / edite / cancele ordens e leia seu histórico de apostas de forma programática. É a mesma API que move a aplicação web da 4casters.

## URL base {#base-url}

Todos os endpoints desta seção têm como raiz:

```
https://api.4casters.io
```

## Convenções {#conventions}

- **Transporte**: somente HTTPS.
- **Codificação**: JSON. Envie `Content-Type: application/json` em cada requisição que tenha corpo.
- **Envelope de resposta**: Com algumas exceções bem marcadas (`/affiliate/getAffiliateCommission`, `/exchange/getOddsForAveragePrice`), cada resposta bem-sucedida vem envelopada: `{ "data": <payload> }`.
- **Identificadores**: os ids de evento, de participante e de ordem são strings `ObjectID` do MongoDB (hex de 24 caracteres).
- **Odds**: todas as odds estão em formato americano (negativas para favoritos, positivas para azarões) salvo indicação em contrário.
- **Tempo**: todas as marcas de tempo são ISO 8601 com `Z` (UTC).

## Autenticação {#authentication}

Quase todos os endpoints exigem autenticação. Faça login uma vez com [POST `/user/login`](/pt-BR/pages/rest/authentication) e depois envie o token de autenticação retornado em cada requisição: consulte [Autenticação](/pt-BR/pages/rest/authentication) para mais detalhes.

## Erros por ordem frente a erros HTTP {#per-order-errors-vs-http-errors}

Os endpoints de "enviar" e "editar" aceitam lotes e retornam resultados por ordem. Uma resposta HTTP `200` bem-sucedida pode conter falhas individuais de ordens dentro de `data.createdSessions[i]`. Consulte a forma do erro por ordem na página de cada endpoint.

Os erros no nível HTTP (`4xx`, `5xx`) são retornados como `{ "error": "<message>" }`.

## Limitação de taxa {#rate-limiting}

Aplicam-se três camadas de limitação de taxa:

- **Global, por IP** — cada requisição à API conta contra um orçamento por IP de **3,000 requisições por janela móvel de 60 segundos** (cerca de ~50 requisições/segundo sustentadas). Ultrapassá-lo retorna `429` com um cabeçalho `Retry-After` (segundos) e o corpo `{ "error": "Too many requests. Please try again later." }`.
- **Rotas de autenticação** (`/user/login`, redefinição de senha, cadastro) têm throttling adicional por IP e por conta.
- **Rotas de enviar / editar / cancelar** são, além disso, limitadas por conta.

Os endpoints de leitura não têm limite por conta: aplica-se somente o teto global por IP.

## Tempos limite {#timeouts}

As requisições que levam mais de **15 segundos** no servidor são abortadas e retornam `503` com o corpo `{ "error": { "message": "Network Error", "code": 503 } }`.

## Atualizações em tempo real {#real-time-updates}

A API REST é complementada pela [API de streaming WebSocket](/pt-BR/pages/streaming/introduction) para ticks do livro de ordens em tempo real e eventos de casamento / liquidação por conta. O token de autenticação que `/user/login` retorna serve para ambas.
